# S1 General Coding Worker

## Outcome

Add a versioned ordinary-coding invocation path beside the unchanged policy-bound firmware path. Both paths reuse the existing Codex process lifecycle, while coding invocations require no firmware policy, lease, board, MCP, relay, or server records. AI evaluation becomes explicitly opt-in.

## Product Scope

- Set the watcher dataclass default, omitted configuration fallback, and example `evaluator_enabled` value to `false`.
- Dispatch explicit `orchestrator-coding-invocation/v1` and the existing firmware invocation separately. Reject unknown explicit schemas.
- For coding invocations, parse lane ID, worker invocation ID, task, run root, resources, prompt and hash, output paths, event-log path, Codex settings, action, and resume identity.
- Keep prompt/output/runtime paths confined to their declared roots and validate prompt bytes against the declared SHA-256.
- Honor model, reasoning effort, service tier, sandbox, and approval settings while retaining the required full-access/never-approve safety floor for this workflow.
- Reuse start, JSONL, stderr, thread capture, PID plus creation identity, terminal state, cancellation, and resume machinery.
- Persist invocation schema and worker invocation ID in controller status and lane events.
- Reject resume when the requested worker invocation ID or thread conflicts with persisted identity.
- Leave the existing policy-bound firmware parser and behavior intact.

## Non-Goals

- No Git identity or result validation yet.
- No generic resource locks yet.
- No scheduler, task database, dependency model, file-ownership protocol, or adapter framework.
- Do not alter `pre-conversion-rollback`.
