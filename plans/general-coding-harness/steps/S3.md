# S3 Coordination and Recovery

## Outcome

Add one generic exclusive named lock for non-Git resources and expose coding identity, waits, claims, conflicts, and invalid results through the existing durable snapshot/event/acknowledgement protocol while preserving firmware observation.

## Product Scope

- Parse coding `resources` as opaque non-empty names and store them in status.
- Map each exact name to a safe deterministic hashed claim filename while retaining the original name in the claim.
- Acquire claims atomically in canonical order; on contention release partial acquisitions before waiting/retry.
- Publish `WAITING_RESOURCE` and never launch Codex until all claims are held.
- Claim records contain resource, lane, worker invocation, PID, and creation identity.
- Release only exact matching owner claims. Reclaim only after complete process evidence proves absence; unknown ownership stays locked.
- Normal short contention is not manager-actionable. Malformed, proven-stale, or excessive waits are durable actionable conditions.
- Extend coding snapshots with schema/invocation/Git/resources/claims/wait/result facts and duplicate branch/worktree conflicts.
- Preserve stable event IDs, priority, at-least-once delivery, and exact acknowledgement.
- Keep application failures distinct from harness failures and preserve all firmware permission/relay/MCP/board/hardware behavior.

## Non-Goals

- No resource type taxonomy, distributed lock service, scheduler, task database, dependencies, file ownership, or automatic work partitioning.
- No user-facing final quick start or disposable end-to-end project yet.
