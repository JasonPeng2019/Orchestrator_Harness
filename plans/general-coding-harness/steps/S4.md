# S4 General-Use Delivery

## Outcome

Make general coding the primary documented entry point and provide a disposable two-worktree integration fixture proving the complete coding path without firmware prerequisites.

## Product Scope

- Add a generic harness configuration, coding invocation, coding result, and named-lock example.
- Make the root quick start/README lead with ordinary coding; retain clearly labeled supported firmware guidance.
- Document branch/worktree split and merge lanes, frozen/candidate/acceptance/promotion roles, exact event acknowledgement, checkpoints/results, locks, and cleanup.
- Remove inaccurate product-wide MCP-Trial wording and firmware-specific forbidden output rejection where it blocks ordinary projects.
- Add a shared disposable integration fixture that creates a Python repo, two branches/worktrees, fake coding controllers, independent Git identities, one contended resource, stale rejection, valid committed results, merge branch, tests, durable events/exact ack, and exact cleanup.
- Keep integration deterministic and Windows-safe.

## Non-Goals

- No scheduler, task database, dependency graph, file ownership, broad adapters, project command enforcement, or physical hardware test.
- Do not remove working firmware support.
