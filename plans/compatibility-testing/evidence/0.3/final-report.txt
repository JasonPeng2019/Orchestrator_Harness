## Report — Step 0.3: `config_overrides` / `service_tier` / `approval_policy` silently dropped for claude-code (bug C17 / U4)

Branch `compat-test-copy`, disposable clone only. **No commit made.** Steps 0.1/0.2 artifacts retained; this step touched only `orchestrator_harness/provider.py`, `orchestrator_harness/invocation.py`, `orchestrator_harness/lane_controller.py`, and tests.

### (1) Reproduction output (`evidence/0.3/repro-silent-drop.txt`)

Same canonical invocation with all three fields, two provider ids:

```
=== provider.id='claude-code'  adapter=ClaudeCodeProviderAdapter
  argv: claude-code --print --output-format stream-json --verbose --model deepseek-v4-flash:0731-cloud --permission-mode bypassPermissions
  carried in argv: []
  dropped from argv: ['config_overrides', 'service_tier', 'approval_policy']

=== provider.id='codex'  adapter=CodexProviderAdapter
  argv: codex exec ... -c approval_policy="never" ... -c service_tier="standard" -c model_provider="ollama" ...
  carried in argv: ['config_overrides', 'service_tier', 'approval_policy']
  dropped from argv: []
```

Confirmed: claude-code accepted the fields at the invocation layer and its adapter silently dropped all three; codex carried all three via `-c`.

### (2) Env-channel design (what I extended, where merged)

Claude Code has no `-c` config channel, so `config_overrides` for claude-code is **honored via the child-process env channel**, merged **after** isolation/allow-list filtering:

- **`ProviderLaunchSpec`** (provider.py) — new defaulted field `env_overrides: Mapping[str, str] = field(default_factory=dict)`. Backward compatible: existing positional callers unchanged; `provider_config_digest()` now includes `env_overrides` so effective config stays in the deterministic digest.
- **Adapter-owned translation** (provider.py):
  - `claude_config_override_env(override)` — maps the alias `model_provider="ollama"` → `{"ANTHROPIC_BASE_URL": "http://localhost:11434", "ANTHROPIC_AUTH_TOKEN": "ollama", "ANTHROPIC_API_KEY": ""}`; accepts explicit `ANTHROPIC_*` assignments verbatim (quotes stripped); **raises `ProviderAdapterError`** for anything that is neither the alias nor an `ANTHROPIC_*` env assignment — fail loud, never drop.
  - `claude_child_env_overrides(spec)` — folds `config_overrides` + `env_overrides` into one validated `ANTHROPIC_*` map (also validates the `env_overrides` field itself).
  - `ClaudeCodeProviderAdapter.build_argv` calls it up front so the standalone adapter contract is fail-loud too; the argv itself stays claude-shaped (no `-c`).
- **Controller merge** (lane_controller.py):
  - `_provider_launch_spec` now translates `invocation.config_overrides` into `spec.env_overrides` for claude-code *inside* the existing `try:` block, so a bad override surfaces as `InvocationError("provider launch settings are invalid: …")`, not an uncaught `ProviderAdapterError`.
  - `apply_provider_env_overrides(child_env, env_overrides)` merges overrides into the **already isolated/allow-listed** child env (or `os.environ` when unisolated); called in `run()` immediately before the process boundary.

Security property proven: inherited `ANTHROPIC_AUTH_TOKEN` is dropped by `isolated_coding_child_environment` and only the *declared* override reaches the child.

### (3) Reject behavior (invocation layer)

In `invocation._provider()` (`invocation.py`), claude-code now rejects with `InvocationValidationError` naming the offending field(s):

```
provider claude-code has no equivalent for field(s): provider.approval_policy, provider.service_tier; Claude Code has no --service-tier or --approval-policy flags
```

- Rejected: `service_tier`, `approval_policy` (both named together when both present).
- Still accepted for claude-code: `permission_mode`, `allowed_tools`, `disallowed_tools`, `mcp_config`, `command`, `model`, `notification`, `config_overrides`.
- Codex unchanged: all three fields stay accepted and carried via `-c`.
