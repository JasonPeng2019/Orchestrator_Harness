# Logging Repair 011 — continuous coverage and complete sprint boundaries

## Goal

Make the next attention sprint self-checking so a long but bounded lane shutdown cannot silently
expire the primary watcher, and so required formal-review and event-selection snapshots are
durably complete rather than reconstructed from `UNKNOWN` placeholders.

## R11 evidence that drives this repair

- The primary managed watcher expired after its manager-heartbeat lease while one lane was still
  completing its bounded checkpoint. That left an unobserved interval before invocation finish.
- Invocation snapshots existed, but no durable `FORMAL_REVIEW_BASELINE_ADVANCED` record existed
  and harness-created pending snapshots were explicitly incomplete.
- All four blocking gates were causally classifiable as `HARNESS_DELIVERY_DELAY`, and the formal
  review was `BUSY_MANAGER_DELAY`; the analyzer itself did not fail. The missing information is
  lifecycle/boundary instrumentation, not another attribution rule.
- Some lanes treated a late response inconsistently. An accepted sprint needs every blocking gate
  to end with receipt/resume or an explicit terminal gate-expired record, never mere controller
  disappearance.

## Required changes

1. **Fail-closed sprint boundary helper**
   - Add one host-only helper used by attention sprint launchers to create/validate a fresh epoch
     boundary.
   - It must require primary heartbeat timeout to exceed the declared bounded sprint lifetime,
     while still remaining greater than the formal-review interval.
   - It must reject a config that could expire before the declared endpoint.
   - This is service-coverage protection only; it must not emit manager activity or infer manager
     presence/idle state.

2. **Complete snapshot helpers**
   - Provide deterministic metadata builders/validation for:
     - `MANAGER_INVOCATION_STARTED` and `MANAGER_INVOCATION_FINISHED`;
     - `FORMAL_REVIEW_BASELINE_ADVANCED` at controller activation and after each review;
     - manager event selection immediately before `MANAGER_EVENT_CLAIMED`.
   - Snapshots must be `complete:true`, list the bounded pending events, and carry a real selection
     reason. Do not manufacture transcript content or infer unobserved work.
   - The sprint helper must fail its readiness/finalize checks when any required boundary is absent
     or incomplete.

3. **Terminal blocking-gate contract**
   - Define and validate one explicit terminal late/expired gate record so a lane that correctly
     refuses stale work is still durably terminal.
   - A blocking event at sprint finalize must have either response receipt plus work resume, or the
     explicit terminal-expired record. Controller exit alone is insufficient.
   - Preserve existing delivery/manager attribution and do not reinterpret a terminal-expired
     lane as an on-time response.

4. **Tests and documentation**
   - Reproduce R11 heartbeat-expiry risk and reject the unsafe boundary before launch.
   - Prove no synthetic heartbeat/activity records are generated by the helper.
   - Prove complete baseline/selection snapshots pass and missing/incomplete ones fail finalize.
   - Prove both terminal gate endings pass finalize and controller exit alone fails.
   - Preserve watcher-disabled no-op behavior.
   - Document the exact next-sprint procedure and metadata-file-only examples.

## Verification

- Full watcher unit suite.
- Full orchestrator-harness unit suite.
- Host practical covering boundary setup, baseline, selection, both terminal gate paths, and final
  coverage validation.
- Compileall, focused Ruff F, focused Pyright.
- Fresh isolated readiness output proving safe coverage config, complete formal baseline and
  selection snapshot, one terminal healthy gate, one terminal expired gate, and drained/no-error
  watcher state.

## Non-goals

- No codex-exec bridge.
- No firmware/server/provider/hardware changes.
- No synthetic manager heartbeat or activity evidence.
- No change to the five causal classifications or silence-inference rules.
