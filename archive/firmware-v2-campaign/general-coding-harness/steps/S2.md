# S2 Git-Safe Completion

Status: completed and archived V1 step; non-operative. The Plan 2 successor is also closed as of
2026-08-21. This file is retained only as implementation history; do not create a task card, lane,
gate, rerun, or product change from it.

## Outcome

Tie each coding invocation to its actual Git repository, linked worktree, branch, base, and starting commit, then accept merge readiness only from a valid current clean branch-tip coding result.

## Product Scope

- Add a small shell-free Git identity module.
- Coding invocations declare repository common directory, worktree root, branch, and base commit.
- Before start, verify the real common directory/worktree, attached branch, existing base, and starting commit. Revalidate worktree and branch on resume.
- Record Git identity in controller status; reject duplicate active coding worktree or branch declarations.
- Apply all Git checks only to coding invocations; preserve firmware behavior.
- Validate `orchestrator-lane-result/v1` for the current coding lane/worker/branch and a real current branch-tip commit.
- Require a clean project worktree while excluding ignored runtime state.
- Validate bounded outcome, summary, and check shapes without executing reported commands.
- Treat firmware results only through the firmware route and never as coding results.
- Emit bounded durable invalid-result evidence and clear it after correction.

## Non-Goals

- No generic resource locks, lock waiting, scheduling, dependency graph, task database, or file ownership.
- No S3 event redesign beyond the minimum existing durable condition path needed to expose invalid results.
- Do not alter `pre-conversion-rollback`.
