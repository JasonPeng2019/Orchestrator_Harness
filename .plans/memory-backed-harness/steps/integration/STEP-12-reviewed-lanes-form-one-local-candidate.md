# STEP-12 - Reviewed lanes form one local candidate

## Outcome

Master integrates the four exact reviewed lane commits onto the clean
integration worktree, pins one candidate, and proves the joined bytes satisfy
the coherent local Standard path, final-context safety, all-off preservation,
terminal outcome, and exact cleanup contracts before any credentialed work.

## Scope and touchpoints

Integration occurs only in
`development/product/integration/checkpoint-20260925`. Master inspects actual
lane diffs and write-boundary overlap, then cherry-picks Lane 3, Lane 4, Lane 1,
and Lane 2 commits in that order. Planning files in the top-level memory repo,
historical worktrees, and frozen harnesses are not product merge inputs.

## Implementation

Require one fresh exact-tip review from each lane under the time-crunch policy.
A lane with correct existing behavior may contribute focused tests only. Resolve
only real merge/interface conflicts; a changed shared candidate/envelope shape
returns to its declared owner and invalidates direct consumers. Record the final
candidate revision, then run the smallest combined selectors: STEP-01/02
EverOS, STEP-03–05 Atlas control, STEP-06/07 coherent preparation/context,
STEP-08 all-off, and STEP-09–11 handoff/review/outcome/cleanup. Add existing
privacy, exact-target, and duplicate-dispatch tests only where the lane diff
touches their shared logic. Do not run broad discovery or packaging.

## Dependencies and integration

Consumes STEP-02, STEP-05, STEP-07, STEP-08, STEP-10, STEP-11, and their four
lane reviews. Produces the only pin authorized for STEP-13/14. Missing live
dependencies do not hold this local step.

## Requirement-fit validation

The integrated bytes—not lane summaries—must show both trusted inputs selected
and safely finalized, all-off completion with zero optional calls, enhanced
handoff preservation, durable review/outcome, and exact cleanup behavior.

**Time-crunch repair gate:** return a lane only for a reproduced defect in the
desired normal MVP path, its used ordinary compatibility/recovery, or a critical
privacy/identity/trust/durability/duplicate-effect/cleanup invariant. Record all
edge, unsupported, theoretical, cosmetic, broad-suite, or non-normal findings in
`KNOWN_ISSUES.md` without correction, blocking, or re-review.

### Fast test suite

Run the exact focused classes/modules named by STEP-01–11 on the integrated pin,
then `git diff --check`. Reuse a passing lane result only for unchanged bytes;
every lane selector runs once on the joined candidate because cross-lane imports
and contracts are new inputs. No full `tests/local` discovery is required.

## Failure scope and recovery

A conflict or failing selector holds only the affected step and its live/native
consumers. Keep other integrated commits and passing checks. Never reset the
integration worktree or discard a dirty lane.

### Fast lane for revisiting old work

Return one bounded finding to the owning lane, integrate the reviewed repair,
rerun its focused suite and only joined selectors that consume the changed
bytes, then repin the candidate.
