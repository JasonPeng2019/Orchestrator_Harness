# STEP-06-1 — Finalize exact accepted-plan context

This step is a derivative of [original STEP-06](../../source-steps/STEP-06-final-context-binds-accepted-plan.md).

Owner: lane 1. This is the complete domain-finalization assignment.

Complete the existing `src/memory_harness/context.py` finalizer and validation, its `preparation.py` and `runtime.py` callers, and `privacy.py`; lane 2 owns the `harness/orchestrator_harness/memory_handoff.py` envelope.

Use the STEP-05-1 prepared state and ROOT's acceptance of an exact plan revision. Finalize a bounded context tied to task, objective, route, accepted plan, repository base, and configuration. Recheck plan-affecting guidance under the remaining bound. Pack mandatory task/plan/security meaning before optional whole items; fail explicit mandatory overflow. Apply recipient privacy and all-off gates before rendering. A stale or revoked plan-affecting source blocks finalization or requires explicit ROOT replan. The context is ready for launch but asserts no observed invocation.

Publish the finalized record and validation contract used by lane 2's STEP-06-2 and STEP-07-2. Evidence: focused final-context tests for proposed versus accepted plans, wrong identity, overflow, optional trimming, privacy, freshness, and all-off.

The immutable context identity binds task, objective, decision, exact accepted plan revision and integrity, repository base/worktree, checkpoint, route, captured configuration, execution role, invocation target, rendered content, recipient, and delivery trace. Record selected, packed, omitted, and actually delivered optional items with provenance; a content, omission, or mandatory-identity change changes the integrity/trace. Recheck plan-affecting procedure eligibility as well as freshness: omit an unrelated ineligible/stale item with a corrected trace, but return a plan-dependent change to ROOT. Mandatory task/plan/base/route and trusted security meaning precede optional cases, procedures, and templates; trim optional items only as whole units. Historical instruction-like text remains labeled evidence, never authority. An approved procedure may use only its separately approved compact representation, not arbitrary truncation under the old approval. Sanitize and authorize every recipient before rendering or remote-bound use. A required task credential uses a validated task-only channel or blocks that dependent action; product control-plane credentials never enter worker context. A changed plan revision requires a new finalized envelope. Unsafe or overlarge mandatory context uses ROOT's established compaction/recovery path or blocks enhanced dispatch, retaining the accepted plan and exact reason. Run `tests.local.preparation.test_final_context_dispatch` and affected `harness/orchestrator_harness/tests/test_memory_handoff.py` cases; an envelope change also invalidates lane 2's handoff checks.

For a revisit, repair only the finalizer or envelope validator and retain valid preparation and acceptance. Rerun direct context tests when plan state, selected guidance, privacy policy, or context limit changes; rerun lane 2's STEP-07 handoff consumer if the finalized envelope changed.
