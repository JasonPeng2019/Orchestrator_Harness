Evidence: affected memory-handoff tests for each plan state, exact envelope identity, all-off, and legacy cards. Finalization is not a claim that launch occurred.

The harness envelope must preserve the domain-finalized identity for task, objective, decision, exact ROOT-accepted plan revision/integrity, repository base/worktree, route, captured configuration, execution role, invocation target, recipient, lane/run, rendered context, and selected/packed/omitted/delivered trace. Bootstrap and native resume validate equivalent meaning, including copied wrong-task/base envelopes and changed payload/integrity. Reject a stale, revoked, mismatched, unreadable, or changed-revision envelope; never silently substitute memory or treat candidate/reviewed plans as accepted. Carry only context already sanitized and authorized for its recipient. Preserve mandatory task/plan/base/route/security meaning and explicit mandatory-overflow failure rather than repacking away a domain error. An unsafe envelope blocks only enhanced dispatch while the accepted plan and reason remain visible. Run affected `harness/orchestrator_harness/tests/test_memory_handoff.py` cases alongside domain final-context tests; prove absent/proposed/reviewed/accepted, wrong identity, all-off, legacy, and ready-versus-observed separation.

For a revisit, repair only the envelope validator, retaining valid domain preparation and acceptance. Rerun direct handoff/context checks when plan state, selected guidance, privacy policy, or context limit changes; rerun STEP-07's launch consumer if the carried envelope changed.
