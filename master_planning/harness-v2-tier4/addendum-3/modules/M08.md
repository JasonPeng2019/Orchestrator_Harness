# M08 - Expensive or External Readiness Proof

## Module contract and selection

| Module type | Decision | Instance IDs | Reason |
|---|---|---|---|
| M08 | OMITTED | N/A | STEP-006 invokes ordinary accepted product commands directly and creates no custom runner, scheduler, observer, transport, or irreversible allocation whose control path needs a separate rehearsal. ROOT performs the exact candidate, command, provider configuration, authorization, workspace-root, record-path, hook-path, and cleanup readbacks inline in M09 immediately before each external allocation. A separate readiness worker would duplicate those launch-time checks without proving another claim. |

## Public interface and compatibility boundary

M08 exposes no active instance. The omission removes only a redundant rehearsal
layer; it removes no product requirement or native evidence obligation. M09 owns
the concrete pre-allocation readback and records any failed prerequisite as an
exact support or authorization gap before provider launch.

## Rules, process, recipe actions, and allowed variations

P01, P04, P09, P12, P13, and P15 govern the remaining external path. If a future
plan introduces a genuinely fragile custom executor or an unproved irreversible
control path, ROOT must amend this module decision before using it. The current
public product commands and product-owned records do not meet that trigger.

## Configured module instances

No M08 instance is configured because its optional readiness/rehearsal behavior
would duplicate M09's mandatory launch-time admission checks.
