# M03 - Independent Verification Asset Construction

## Module contract and selection

| Module type | Decision | Instance IDs | Reason |
|---|---|---|---|
| M03 | SELECTED | MI-NORMAL-VERIFY-ASSETS, MI-NORMAL-LIVE-TEST-ASSETS, MI-FL2-S1-ASSET-PATCH, MI-FL2-S1-ASSURANCE-PATCH, MI-FL2-S1-LIVE-PATCH | Atomicity, lifecycle, CLI, recovery, and cleanup behavior need independent deterministic oracles; STEP-006 owns the two still-missing correction-limit tests without reopening completed STEP-003. Native-provider proof is limited to M09. |

## Public interface and compatibility boundary

Consumes named acceptance claims, scenarios, oracle properties, an admitted source base, and an exclusive verification-asset write scope. Produces one independently owned asset tip and claim map for M04/M07/M09. A changed scenario, oracle, coverage obligation, or public asset interface invalidates consumers; test-code mechanics do not.

## Rules, process, recipe actions, and allowed variations

P01 through P10 and P13 through P15 apply. ROOT predefines behavior, triggers, expected results, protected semantics, and oracle strength. VERIFICATION_WRITER chooses only fixture and assertion mechanics. Product behavior and locked configuration remain untouched.

| Order | Recipe action ID | Project-specific action/process | Allowed parameterization | Decision owner |
|---|---|---|---|---|
| 1 | M03-A1 | Confirm every requested asset closes one SRC-009 gap or protects a changed shared invariant and drop trusted duplicates | Gap-to-asset mapping | ROOT |
| 2 | M03-A2 | Materialize each ROOT-defined scenario, trigger, expected behavior, oracle, and selection before code | Test mechanics only | ROOT |
| 3 | M03-A3 | Assign the shared verification surface to one writer | No internal writer fan-out | ROOT |
| 4 | M03-A4 | Author only the declared acceptance assets and disposable fixtures | Declared asset paths | ROOT |
| 5 | M03-A5 | Run asset compile, discovery, and fake-only self-tests | No real target CLI or credential | ROOT |
| 6 | M03-A6 | Inspect asset diff for oracle strength, coverage fidelity, ownership collision, and scope | Complete DEL-002 diff | ROOT |
| 7 | M03-A7 | Publish one independently owned tip, claim map, commands, and handoff | Launcher-bound result path | ROOT |

M03-A2/A5 bind each changed control branch to an executable typed-fake or disposable
test, using the coverage obligations in STEP-006. Include unchanged imported helpers in
the copied fixture. Source-string checks supplement execution; they do not prove
that a custom-adapter branch, wait producer, parser rejection or retired-epoch read
can reach the intended decision. Validate candidate/configuration values through
their executable binding, not a matching literal in a comment. Publish this mapping
with the owning asset handoff so STEP-006 can preserve unaffected proof.

The current version 3.7 deterministic delta is exactly the missing REQ-008/009
candidate-controller boundary proof. Add focused controlled-provider tests that
execute the candidate controller for (a) valid recovery after the fifth correction
on the sixth provider attempt and (b) six invalid exits with exactly five prompts,
no sixth prompt, exactly one final provider_exited_no_result, preserved native
session/lease identity, and cleanup-before-continuation evidence. Reuse existing
adapter argv tests and deterministic malformed-result fixtures. Constructed oracle
arrays or a third-attempt success cannot substitute for these candidate executions.

### Historical matrix-control work (version 3.5; superseded by version 3.7)

The following block records why the paused control work existed. BOUND-020 removes
it from prospective dispatch: do not review, integrate, qualify, repair, or run
the custom matrix runner, scheduler, observer, timeout, prompt-made fixture, or
multi-launch scenario. The version 3.7 M03 live-asset path can touch only a small
direct-canary descriptor or post-terminal durable-record parser whose fixed
semantics are already defined by M09.

The Series 9 through decision820 control artifacts remain readable historical
evidence only. No M03 card consumes their driver, runner, scheduler, observer,
timeout, checkpoint, fixture, or wrapper. Their accepted facts may inform retained
credit; their unintegrated bytes have no prospective successor.

One asset writer overlaps M02 in a separate worktree and writes only the declared new asset paths. Its later review/check roots are also disjoint.

#### Resources and side effects

Disposable repositories and fake processes only. Every fixture cleans by exact identity and retains failure state only when required for diagnosis.

#### Checks and acceptance

One writer and one later two-member campaign. It overlaps the larger product build and avoids a serial post-implementation test-authoring phase.
