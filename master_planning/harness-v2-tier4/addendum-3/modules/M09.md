# M09 - Practical or External Validation

## Module contract and selection

| Module type | Decision | Instance IDs | Reason |
|---|---|---|---|
| M09 | SELECTED | MI-NORMAL-LIVE-MATRIX, MI-FL2-S2-LIVE-RECONCILE | SRC-009 requires a full Windows matrix and explicit other-platform gaps plus a state-verified affected-only continuation at the STEP-006 progress bound |

## Public interface and compatibility boundary

Consumes one authorized platform/provider scenario contract, exact candidate/runner/target/resource state, readiness PASS, topology, runtime IDs, claim, checkpoint, and containment triggers. Produces one contained terminal attempt pool. Changed runner, target, scenario, candidate, authorization, host, observer, or consumed external state invalidates dependent practical credit.

## Rules, process, recipe actions, and allowed variations

P01 through P15 apply. ROOT defines and authorizes the attempt; no worker may start or retry one. Observation starts first and remains read-only except P15 containment. Platform runner sets and provider target sets serialize; ordinary failures complete the feasible matrix; all cleanup is exact-identity based.

| Order | Recipe action ID | Project-specific action/process | Allowed parameterization | Decision owner |
|---|---|---|---|---|

| 2 | M09-A2 | Create ATTEMPT-LIVE-MATRIX and bind execution/observation lane, worktree, invocation, process-tree, result, claim, and cleanup IDs plus every platform runner and provider target set's ROOT process, monitor, controller tree, worker provider-session, v2 lane/run, lease, and consumed-state IDs | Runtime values recorded at dispatch | ROOT |

## Configured module instances

### MI-NORMAL-LIVE-MATRIX - M09: Authorized platform and native-provider verification matrix

#### Purpose

Own the one practical external attempt that decides REQ-017 from platform/provider admission through observation, cleanup, and complete result join.

#### Coverage

REQ-017, REQ-019, REQ-020, OUT-004, OUT-005, EXT-002, CHECK-PLATFORM-WINDOWS, CHECK-PLATFORM-MACOS, CHECK-PLATFORM-LINUX, CHECK-LIVE-1 through CHECK-LIVE-16, GATE-LIVE.

#### Selection basis

Selected because SRC-009 requires real Windows/macOS/Linux primitive proof and installed target-CLI proof; static and synthetic checks cannot satisfy it. One executor and one observer are the minimum independent topology.

#### Owner and roles

CARD-LIVE-EXECUTION=PRACTICAL_EXECUTOR, CARD-LIVE-OBSERVATION=PRACTICAL_OBSERVER. ROOT governs authorization, target/scenario, attempt, claim, routing, join, and every decision.

#### Preconditions

Static acceptance includes REQ-021 clearance and current readiness PASS exists; ROOT has the current executing platform runner identity with workspace-confined roots; recorded user provider authority covers the current targets/configs; LOCK-LIVE-MATRIX is free; both isolated lanes are prepared under BOUND-013.

#### Inputs

Accepted candidate, readiness result, BOUND-013, platform runner identities, applicable provider authorization, target identities, practical runner, platform/provider scenarios, ATTEMPT-LIVE-MATRIX, LOCK-LIVE-MATRIX, both execution lane/worktree/invocation/process-tree IDs, per-runner/per-target ROOT/monitor/controller/worker provider-session/v2 lane/run/lease/consumed-state IDs, and handoffs.

#### Outputs and results

One RESULT-LIVE-POOL with executor and observer results, per-unit checkpoints, disagreements, target state, and cleanup. Every allocated resource is terminal or terminal-visible.

#### Concurrency and isolation

Observer and executor overlap, with observation active first and separate roots. Target sets serialize inside the executor under one exclusive claim.

#### Resources and side effects

Uses user-authorized installed CLIs and credentials only in BOUND-013 workspace-confined disposable repositories. Exact process/lease identities govern stop and cleanup. No unrelated project or publication.

#### Checks and acceptance

CHECK-PLATFORM-WINDOWS and all applicable CHECK-LIVE-1 through CHECK-LIVE-16 cells run now; CHECK-PLATFORM-MACOS/LINUX and their full cells retain native gaps under BOUND-014. M05 and ROOT decide GATE-LIVE after complete join.

#### Failure and exception routes

Product/practical failures close safely then go to M05; missing authority stops before allocation; support/observer faults isolate claims; P15 contains live harm; no exception exists.

#### Prior results and change effects

Practical PASS is reusable only when candidate, target/config identity, runner, host environment, authorization, and each consumed external/resource state are verified unchanged.

#### Repeat, join, and terminal behavior

Complete feasible units despite ordinary failures, cleanup, and join once. Interruption checkpoints same attempt; new attempt requires ROOT. Terminal output feeds M05.

#### Cost and critical-path effect

One full Windows matrix, three serialized shipped-provider target sets crossed with applicable profiles, sixteen checkpointed feature families, and one overlapping observer; macOS/Linux execution adds no current wait. This is required external cost with no duplicate practical pass.
