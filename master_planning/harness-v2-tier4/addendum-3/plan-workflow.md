## 2. Goal, exclusions, and acceptance outcomes

Starting from `harness-single` at `f4328b177177a3aa71bf5f064b88ad6033b3d903`, implement every requested operational tweak with the smallest portable correction, preserve accepted behavior outside changed contracts, complete repeated source audits, and execute the full real feature matrix on Windows. Compile the same matrix for macOS and native-storage Linux, but record their missing-runner rows as explicit gaps and finish all independent work. This is the second addendum, named `addendum-3` to continue the existing directory convention. `frozen-harness` is the unchanged execution control plane; no planned execution occurs during plan authoring.

Tier choice: Tier 1 cannot credibly contain the coupled queue/controller/recovery changes and independent proof. Tier 2 still leaves substantial verification assets and stateful live testing with one context. Tier 3's single integration cycle does not express the repeated audit/repair and live-state checkpoints. Tier 4 uses the existing six coherent gates, one serial product writer, a disjoint verification writer, and direct ROOT workers. No additional orchestration tier or service is justified.
