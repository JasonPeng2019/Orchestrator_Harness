# M08 - Expensive or External Readiness Proof

## Module contract and selection

| Module type | Decision | Instance IDs | Reason |
|---|---|---|---|
| M08 | SELECTED | MI-NORMAL-LIVE-READINESS, MI-FL2-S2-LIVE-READINESS | The real matrix needs cold readiness proof and affected-only readiness replay after accepted control-asset repair |

## Public interface and compatibility boundary

Consumes the exact expensive procedure, disposable fake inputs, control properties, prohibited effects, and expected result. Produces one non-product readiness result for M09. Changed candidate, runner, fixture, checkpoint, environment, fake topology, or property invalidates only its dependent readiness credit.

## Rules, process, recipe actions, and allowed variations

P01 through P15 apply. Both fragile-runner and external-control rehearsal profiles are selected because the real matrix consumes both. ROOT fixes every property and fake; CHECKER performs comparisons and observations only. Rehearsal can never satisfy REQ-017.

| Order | Recipe action ID | Project-specific action/process | Allowed parameterization | Decision owner |
|---|---|---|---|---|
| 1 | M08-A1 | Compare prior readiness candidate, runner, fixture, checkpoint, host, and fake-topology inputs and reuse only an unchanged PASS | Cold or checkpoint-resume entry | ROOT |
| 2 | M08-A2 | SELECTED: Run one side-effect-free fake and verify arguments, runtime IDs, timing fields, command, output, checkpoint read/write, resume, cleanup, and exit | Disposable runner profile | ROOT |
| 3 | M08-A3 | SELECTED: Exercise fake admission, target binding, authorization shape, observation, abort, idempotence, recovery, cleanup, and terminal closure | Disposable external-control profile | ROOT |
| 4 | M08-A4 | Read back that no product, real target CLI, credential, service, hardware, or scarce namespace was consumed | Exact no-real-side-effect proof | ROOT |
| 5 | M08-A5 | Publish separate runner/control property results and only the input comparison needed for reuse | HANDOFF-READINESS | ROOT |
| 6 | M08-A6 | On failure rerun failed, affected, or uncertain properties from the earliest required action and preserve unaffected PASS | No broad replay | ROOT |

## Configured module instances

### MI-NORMAL-LIVE-READINESS - M08: Disposable real-matrix control rehearsal

#### Purpose

Prove fragile practical control machinery cheaply before the authorized real target-CLI matrix.

#### Coverage

REQ-017 readiness dependency, OUT-004 support, EXT-001, CHECK-READINESS.

#### Selection basis

Selected because the live runner starts and observes child processes, checkpoints units, exercises hooks, and must prove cleanup. A disposable rehearsal is cheaper than losing a real attempt.

#### Owner and roles

CARD-LIVE-READINESS=CHECKER. ROOT governs dispatch, consumes HANDOFF-READINESS, and retains every decision and acceptance action.

#### Preconditions

Static acceptance is current; the DEL-002 readiness fixture exists; WT-READINESS is isolated; no live claim or credential is allocated.

#### Inputs

Accepted candidate revision, fixture/runner, fake target/resource IDs, expected control observations, LANE-READINESS, WT-READINESS, INVOCATION-READINESS, PROCESS-TREE-READINESS, and HANDOFF-READINESS.

#### Outputs and results

One PASS or exact failed/uncertain readiness property, input comparison for reuse, and cleanup result. It is never a product pass.

#### Concurrency and isolation

Serial before M09. Uses its own linked worktree, disposable temporary roots, cache, and result path.

#### Resources and side effects

Disposable repositories, files, fake processes, and fake leases only. Cleanup is verified by exact identity. Real CLIs, credentials, and scarce namespaces are prohibited.

#### Checks and acceptance

CHECK-READINESS covers runner and external-control profiles together because M09 consumes both. ROOT accepts readiness only after direct readback.

#### Failure and exception routes

Failure blocks only M09 and reruns affected properties. A real side effect or lost containment triggers P15. No exception exists.

#### Prior results and change effects

Reuse PASS only when candidate, runner, fixture, checkpoint schema, host environment, and fake topology remain unchanged.

#### Repeat, join, and terminal behavior

One worker lane and no fan-out. Resume from earliest required readiness property; success activates no real attempt until ROOT separately authorizes it.

#### Cost and critical-path effect

One cheap fake launch before the expensive matrix. Its expected prevention payoff exceeds its setup cost because all later target sets reuse the same control path.
