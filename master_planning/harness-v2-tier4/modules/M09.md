# M09 - Practical or External Validation

## Module contract and selection

| Module type | Decision | Instance IDs | Reason |
|---|---|---|---|
| M09 | SELECTED | MI-NORMAL-LIVE-MATRIX, MI-FL2-S2-LIVE-RECONCILE | Part XIX requires a cold real matrix and a state-verified affected-only continuation at the STEP-006 progress bound |

## Public interface and compatibility boundary

Consumes one authorized real scenario contract, exact candidate/target/resource state, readiness PASS, topology, runtime IDs, claim, checkpoint, and containment triggers. Produces one contained terminal attempt pool. Changed target, scenario, candidate, authorization, runner, host, observer, or consumed external state invalidates dependent practical credit.

## Rules, process, recipe actions, and allowed variations

P01 through P15 apply. ROOT defines and authorizes the attempt; no worker may start or retry one. Observation starts first and remains read-only except P15 containment. Target sets serialize; ordinary failures complete the feasible matrix; all cleanup is exact-identity based.

| Order | Recipe action ID | Project-specific action/process | Allowed parameterization | Decision owner |
|---|---|---|---|---|
| 1 | M09-A1 | Verify user authorization, exact target/config identities, accepted candidate, readiness PASS, and free LOCK-LIVE-MATRIX before allocation | One declared matrix attempt | ROOT |
| 2 | M09-A2 | Create ATTEMPT-LIVE-MATRIX and bind execution/observation lane, worktree, invocation, process-tree, result, claim, and cleanup IDs plus every target set's ROOT process, monitor, controller tree, worker provider-session, v2 lane/run, lease, and target-state IDs | Runtime values recorded at dispatch | ROOT |
| 3 | M09-A3 | Launch only executor plus observer and serialize the shipped target sets under one claim | No undeclared topology | ROOT |
| 4 | M09-A4 | Start read-only independent observation before each behavior it must observe | P15 containment signal only | ROOT |
| 5 | M09-A5 | Execute four declared real scenarios per target set and record actions, timing, output, target state, and failures | Complete feasible matrix | ROOT |

| 9 | M09-A9 | Join executor and observer results exactly once and send the complete pool to M05 | No product repair inside attempt | ROOT |

## Configured module instances

### MI-NORMAL-LIVE-MATRIX - M09: Authorized native verification matrix

#### Purpose

Own the one real external attempt that decides REQ-017 from admission through observation, cleanup, and complete result join.

#### Coverage

Selected because SRC-002 explicitly requires real installed target-CLI proof; static and synthetic checks cannot satisfy it. One executor and one observer are the minimum independent topology.

#### Outputs and results

One RESULT-LIVE-POOL with executor and observer results, per-unit checkpoints, disagreements, target state, and cleanup. Every allocated resource is terminal or terminal-visible.

#### Concurrency and isolation

Observer and executor overlap, with observation active first and separate roots. Target sets serialize inside the executor under one exclusive claim.

#### Resources and side effects

Uses user-authorized installed CLIs and credentials only in disposable repositories. Exact process/lease identities govern stop and cleanup. No unrelated project or publication.

#### Checks and acceptance

CHECK-LIVE-1 through CHECK-LIVE-4 run for every shipped target set. M05 and ROOT decide GATE-LIVE after complete join.

#### Failure and exception routes

Product/practical failures close safely then go to M05; missing authority stops before allocation; support/observer faults isolate claims; P15 contains live harm; no exception exists.

#### Prior results and change effects

Practical PASS is reusable only when candidate, target/config identity, runner, host environment, authorization, and each consumed external/resource state are verified unchanged.

#### Repeat, join, and terminal behavior

Complete feasible units despite ordinary failures, cleanup, and join once. Interruption checkpoints same attempt; new attempt requires ROOT. Terminal output feeds M05.

#### Cost and critical-path effect

One external matrix, three serialized target-set setups, four units per set, and one overlapping observer. This is required external cost with no duplicate live pass.
