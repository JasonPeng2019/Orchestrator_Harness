# M02 - Product Implementation and Repair Tranche

## Module contract and selection

| Module type | Decision | Instance IDs | Reason |
|---|---|---|---|
| M02 | SELECTED | MI-NORMAL-PRODUCT, MI-FL2-S1-PRODUCT-PATCH, MI-FL2-S1-INTEGRATION-PATCH | DEL-001 needs coherent implementation; scoped product and integration-owned corrections need singular writers without replaying the normal overhaul |

## Public interface and compatibility boundary

Consumes an admitted clean source allocation, complete DEL-001 behavior contract, realistic failure brief, and preserved credit. Produces one reviewable clean tip plus producer checks. Public behavior, write boundary, correction owner, or output shape changes invalidate consumers; internal implementation mechanics do not.

## Rules, process, recipe actions, and allowed variations

P01 through P11 and P13 through P15 apply. One PRODUCT_WRITER owns the entire coherent product tip. Candidate code may be reused only where it already satisfies SRC-002; obsolete parallel abstractions are deleted after reference and replacement-coverage proof. New complexity must satisfy SRC-003's correctness or four-to-one value boundary.

|---|---|---|---|---|

| 6 | M02-A6 | Inspect the complete diff for scope, accidental files, dead candidate machinery, debug output, and requirement coverage | Whole DEL-001 diff | ROOT |
| 7 | M02-A7 | Freeze and publish one reviewable clean tip with current checks and handoff | Launcher-bound result path | ROOT |
| 8 | M02-A8 | On a ROOT-authored material return, repair the complete compatible pool in the same logical task and rerun only implicated self-checks | Invocation reuse or structured handoff under P02 | ROOT |

The sole product writer may overlap STEP-003 only because DEL-002 paths are protected. No second process may mutate WT-PRODUCT.

#### Resources and side effects

Source changes and producer-local test execution occur only in WT-PRODUCT. No live provider, credential, hardware, publication, or frozen-harness mutation is allowed.

#### Checks and acceptance

CHECK-PRODUCT-SELF catches producer mistakes; M04 independently reviews/checks; ROOT alone decides GATE-PRODUCT.

Correct product self-check failure remains local. Material campaign findings return as one ROOT-authored batch. Test-only/support/ambiguity routes go to M05 or ROOT; no exception exists.

On repair, preserve actions and PASS whose declared inputs are unchanged; rerun the earliest affected self-check and publish a new frozen tip.

#### Repeat, join, and terminal behavior

The logical product task repeats only for a failed or undecidable required product criterion. It joins no peer internally and ends only on ROOT semantic acceptance, unrecoverable error, or stall.

#### Cost and critical-path effect

One broad implementation launch plus pooled repair when required. It is the likely construction critical path and overlaps the independent asset branch.
