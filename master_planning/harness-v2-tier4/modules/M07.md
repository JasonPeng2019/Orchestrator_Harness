# M07 - Accumulated Final Assurance

## Module contract and selection

| Module type | Decision | Instance IDs | Reason |
|---|---|---|---|
| M07 | SELECTED | MI-NORMAL-FINAL-ASSURANCE, MI-FL2-S2-ASSURANCE-RECONCILE | Cross-deliverable risk requires a cold audit/safeguard, while Series 2 must resume only invalidated assurance units |

## Public interface and compatibility boundary

Consumes one integrated release revision, complete goal, accepted deliverable results, final audit contract, static unit/input map, and prior checkpoint. Produces one complete final pool for M05. Changing release unit, selected path, audit surface, unit definition, input map, or checkpoint semantics invalidates consumers.

## Rules, process, recipe actions, and allowed variations

P01 through P11 and P13 through P15 apply. Both audit and safeguard are selected and independent, so they launch concurrently. The safeguard alone owns full static suite commands and resumes conservatively; the audit remains open only as to findings.

| Order | Recipe action ID | Project-specific action/process | Allowed parameterization | Decision owner |
|---|---|---|---|---|
| 1 | M07-A1 | Confirm both accepted deliverables and integration result belong to one declared release unit | Exact integrated revision | ROOT |
| 2 | M07-A2 | Select both FINAL_PRODUCT audit and accumulated safeguard because cross-process overhaul risk requires them | No optional third path | ROOT |
| 3 | M07-A3 | Launch audit and safeguard concurrently with disjoint worktree, cache, and result roots | Two internal members | ROOT |
| 4 | M07-A4 | Audit the accumulated integrated target rather than superseded product or asset tips | Whole release surface | ROOT |
| 5 | M07-A5 | Run CHECK-U1 through CHECK-U5 with conservative inputs, per-unit checkpoint, ordinary-failure continuation, and earliest-required resume | Five independently runnable units | ROOT |
| 6 | M07-A6 | Finish every feasible selected path and join one complete final pool | Dependency skip only for exact prerequisite | ROOT |
| 7 | M07-A7 | Send the complete final pool and checkpoint to MI-NORMAL-STATIC-VERDICT | No repair or acceptance inside M07 | ROOT |

## Configured module instances

### MI-NORMAL-FINAL-ASSURANCE - M07: Whole-release audit and safeguard

#### Purpose

Produce the one complete static result pool over the integrated release unit before real external validation.

#### Coverage

REQ-001 through REQ-016, OUT-001, OUT-002, GATE-STATIC.

#### Selection basis

Selected because the overhaul crosses records, CLI, processes, queues, packaging, and portability. Deliverable-level checks cannot alone expose cross-seam regressions.

#### Owner and roles

CARD-FINAL-REVIEW=REVIEWER, CARD-FINAL-CHECK=CHECKER. ROOT governs both dispatches, consumes both handoffs, owns checkpoint and join, and retains every decision and acceptance action.

#### Preconditions

HANDOFF-INTEGRATION identifies one clean integrated revision; accepted DEL-001/DEL-002 results and unit definitions are current; two isolated allocations exist.

#### Inputs

Integrated revision, requirements, accepted results, audit charter, CHECK-U unit/input map, prior checkpoint, both final lane/worktree/invocation/process-tree IDs, and handoffs.

#### Outputs and results

One RESULT-FINAL-POOL containing complete audit findings, every feasible unit result, dependency skips, checkpoint, and credit map.

#### Concurrency and isolation

ROOT launches both members before waiting. They consume the same revision but use distinct worktrees, caches, and result roots.

#### Resources and side effects

Static source reads, test caches, disposable fake processes, and result/checkpoint writes only. No live target CLI or credential.

#### Checks and acceptance

FINAL_PRODUCT review plus five independently runnable static units. M05 and ROOT decide GATE-STATIC.

#### Failure and exception routes

Ordinary failures complete the pool; support faults isolate dependent claims; P15 is unavailable absent live external effects; no exception exists.

#### Prior results and change effects

Cold run executes all units. A later candidate reuses only unaffected PASS and starts at the earliest required member of the invalidated set.

#### Repeat, join, and terminal behavior

Both selected paths complete, then join once. Compatible findings batch before repair. M05 consumes the pool; no M07 repair occurs.

#### Cost and critical-path effect

Two overlapping worker launches and five checkpointed units form the static cost center; this avoids serial audit-plus-suite time and full reruns.
