## 9. Rules the runner applies (carried into every loop)
- **Guiding principle:** working product, efficiently — not perfect. No gold-plating.
- **Triage:** reviewer classifies functional-defect (admit+fix) vs extraneous
  (log to out-of-scope ledger, drop). Reviewer recommends; the single orchestrator
  decides. `scope_policy` = `<knob values>`.
- **Scoping:** passed registry locks passed test IDs; only gap tests re-run; a
  change re-runs only still-failing gap tests + failed unit tests + new tests for
  that change. `gap_scope` = `<change | all-failing>`. Test-ID scheme = `<...>`.
- **Termination (no iteration cap):** stop each loop on success, stall, or
  unrecoverable error. `stall_threshold` = `<N>`. Stall triggers: no-progress,
  same-signature failure, thrash/oscillation (soft — passed set must trend up),
  scope-creep churn (only-extraneous findings).
- **Parallelism rules:** fan-out only for doing (test authoring, test execution)
  over the disjoint slices above; code-writing singular+serial; all fan-out merges
  to one orchestrator triage; never split decision-making.
